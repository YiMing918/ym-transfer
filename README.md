## 功能一览

| 功能 | 说明 |
|---|---|
| 免注册上传 | 打开网页就能传，不收账号、不收邮箱 |
| 大文件直传 | 单文件最大 5 GB，浏览器直传 R2，不经过服务器中转 |
| 有效期可选 | 1 / 6 / 12 小时、1 / 3 / 7 天，到期自动删除 |
| 下载次数可选 | 不限 / 1 次 / 5 次 / 10 次，用完链接立即失效（原子计数，并发打开也不会超发）。计数口径：计的是「经下载页领取直链的次数」，每次领到的直链 1 小时内有效；链接预览/扫描不会耗次数 |
| 随机链接 | 链接 ID 为 128 位随机值，猜不到；拿到链接的人都能下载 |
| 自动清理 | 定时清理（每 6 小时）+ 访问过期链接时顺手删 + R2 生命周期 10 天兜底，三层保险 |
| 防刷限流 | 同一 IP 每小时最多创建 10 次上传（IP 只存哈希，不存明文） |
| 容量保护 | 全站 10 GB 上限（免费 R2 额度），满了会明确提示等旧文件过期 |
| 站点统计 | 首页可见已用空间与文件数（公开接口 `/api/stats`） |

## 怎么用

1. 打开站点，点「选择文件」（一次传 1 个文件，单个不超过 5 GB）；
2. 选有效期（1 / 6 / 12 小时、1 / 3 / 7 天）和下载次数（不限 / 1 次 / 5 次 / 10 次）；
3. 点「开始上传」，传完复制下载链接发给对方；
4. 对方打开链接直接下载，下载文件名就是原文件名（中文名正常）。

链接到期或下载次数用完就失效；文件在到期后删除，次数用完的会在 1 小时内删除（让已经领到直链的人把文件下完），不用手动清理。

## 技术原理

Cloudflare Pages + Pages Functions + R2 + D1，零构建步骤，全部跑在免费额度内。

- **上传走 R2 预签名 PUT 直传**：浏览器直接把文件 PUT 到 R2，不经过 Worker/Function（Worker 单请求有大小上限，传大文件必须绕过它；单次 PUT 上限 5 GB）。
- **下载走 R2 预签名 GET 跳转**：`/d/<链接ID>` 查元数据后 302 跳到 R2 的预签名地址，文件字节不经过 Worker。
- **元数据存 D1**：随机链接 ID、原文件名、大小、过期时间、下载次数与上限。下载计数在有上限时用条件更新先原子占位再放行，并发请求不会把次数超发。
- **过期清理三条线**：GitHub Actions 每 6 小时调 `/api/cleanup`（带密钥校验；对象删除成功后才删记录，删失败的下次重试）；访问到过期/用完链接时顺手删；R2 桶生命周期 10 天兜底。
- **容量口径**：未过期的已就绪文件 + 保留期（6 小时 10 分）内新建的待上传占 10 GB 上限，超了返回 413。保留期不短于上传地址有效期（6 小时）+ 10 分钟缓冲，保证慢速大文件传满全程记录都在、传完能确认。
- **限流**：同一 IP 每小时最多创建 10 次上传（IP 只存哈希），超了返回 429。

## 部署

见 [DEPLOY.md](DEPLOY.md)，从建桶建库到部署后自测，一步一步写好了。部署前先打开仓库根目录的 `preview.html` 确认界面。

要点提醒：绑定与密钥都在 Pages 后台配，仓库里只有 `wrangler.toml.example` 示例（无真值）；仓库中出现的默认子域地址均为示例，换成你自己的即可。

## 别人部署和本站不一样的地方（Fork 差异）

1. **存储与数据库是空的**：R2 桶与 D1 库要自己建；本站已有的文件、链接不会过去（数据在部署者的 R2/D1 里，不在代码里）。按 DEPLOY.md 建同名桶和库、执行 `schema/0001_init.sql` 和 `schema/0002_add_max_downloads.sql`，功能就一样，但历史文件仍然没有——文件本体从不进仓库。
2. **密钥必须自己生成**：R2 的 S3 凭据（`R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`）与清理密钥（`TASK_SECRET`）不在仓库里；部署时自己在 Cloudflare 生成，分别填进 Pages 后台与 GitHub Secrets。没有密钥就签发不了上传地址——这是故意的，密钥不能共享。
3. **绑定与变量在后台配，仓库里没有真实资源标识**：`database_id`、R2 端点（账号 ID）这些值不进仓库，只有 `wrangler.toml.example` 示例。部署时按 DEPLOY.md 在 Pages 后台绑定你自己的库和桶、填你自己的端点，不存在「照原样部署绑到别人资源」的问题。
4. **定时清理要自己配**：`.github/workflows/cleanup.yml` 每 6 小时调一次清理接口，需要配 `SITE_URL` 与 `TASK_SECRET` 两个 GitHub Secrets；不配的话过期文件只靠「访问过期链接时顺手删」，不会定时删。若你的 GitHub 定时任务经常迟到，也可以另加一层外部补发兜底（可选）。
5. **10 GB 上限人人一样**：这是 Cloudflare 免费 R2 的上限，不是本站特有的。想存更多只能付费升级 R2，然后改代码里的容量常量（`functions/api/upload-init.js`、`functions/api/stats.js`、`public/index.html` 三处一起改）；单文件仍受 5 GB 单次 PUT 上限约束，超过要改成分片上传，目前代码不支持。
6. **域名不同**：默认是 `xxx.pages.dev` 这样的默认子域，自己的域名要在 Pages 里另行绑定。
7. **代码功能完全一样**：上传、下载、过期、限流、统计、中文界面都在代码里，部署后直接就有，不用再配。

## 常见问题

- **传到一半关页面会怎样？** 这个文件不会生成可用链接；未完成的上传记录会在上传地址失效后（约 6 小时）被定时清理掉，不占长期空间。
- **链接发错人了怎么办？** 链接没法单独撤销，可以等它到期自动失效。有效期选得越短，风险窗口越小，敏感文件建议选 1 小时 + 下载 1 次。
- **为什么提示空间不足？** 全站 10 GB 是所有使用者共用的（你自己部署就是你一个人用），等最早的文件过期释放，或换小一点的文件。
- **对方下载慢？** 下载是对方浏览器直接从 R2 拉文件，不经过本站服务器，速度取决于对方网络与 R2 节点。
- **能传 5 GB 以上吗？** 不能。单次 PUT 的上限就是 5 GB，要传更大的请先分卷压缩。

## 已知边界

- **上传地址在过期前可重复 PUT**：预签名 PUT 地址有效 6 小时，确认上传后到地址过期前，持有该地址的人可以覆盖同一文件对象（预签名地址本身无法撤销）。因为本站是无注册的临时分享、链接 ID 本身就是凭证，风险窗口等同于分享链接泄露；若要彻底关掉，需要确认上传后把对象复制到新键并删旧对象——那会产生一笔与文件等大的额外流量与复杂度，本版未采用，记录在此供取舍。
- **下载次数计的是「领取」**：经下载页领到直链后，直链在有效期内（最长 1 小时）可反复下载，这是预签名直链的固有形态，无法按真实下载次数计量。

## 版本历史

- **v1.1.0（2026-11-14）**：三方审查后的一轮边界修复——待上传保留期与上传地址有效期对齐（6 小时 10 分），慢速大文件不再中途被清记录、有效期改为从上传完成起算；预签名 PUT 把声明大小签进签名，大小对不上时立即删除错对象；下载计数改为计数失败就关门（不再抖动时免费放行）、HEAD 探测与链接预览/扫描 UA 不再耗次数、次数用完不再当场删文件（改为收紧有效期到 1 小时，已领直链的下载不中断）、直链有效期不超过分享剩余期；常量收敛到 `functions/_lib/consts.js` 一处；清理密钥改恒定时间比对；本地 mock 的 D1 返回形状与真 D1 对齐（原子计数分支本地可测了）；cleanup 工作流「未配跳过」修好、新增 CI 在 push/PR 时跑全部测试套件；前端修上传中拖拽冲乱界面、非 JSON 响应提示、2xx 判定等；文档订正一次传 1 个文件、IP_SALT 说明、部署双路说明；schema 0003 删冗余索引（可选执行）。
- **v1.0.1（2026-11-12）**：全量检查后的一组修复——清理任务改为「R2 对象删除成功后才删记录」，删失败的留到下次重试（此前失败会丢记录、对象成孤儿）；有下载次数上限的链接改为条件更新原子计数，并发打开不再超发；README 补全至全站统一规格（徽章、目录、功能表、常见问题、版本历史）。
- **v1.0（2026-11-11）**：首版上线。浏览器直传 R2（预签名 PUT，单文件 5 GB）+ D1 元数据；有效期 1/6/12 小时与 1/3/7 天、下载次数 不限/1/5/10；同 IP 每小时创建 10 次限流；清理三层（定时清理、过期懒删、R2 桶 10 天生命周期兜底）。
