# YM 传文件

浏览器里直接传文件，不用注册、不用装 App、不用填邮箱，传完给一个下载链接，过期自动删除。

- **怎么用**：打开站 → 点「选择文件」→ 选有效期（1 / 3 / 7 天）→ 点「开始上传」→ 传完复制下载链接发给对方，对方打开链接就能下载。
- **单文件最大 5 GB**；**站内总共只有 10 GB** 空间（免费 R2 上限），满了会提示等旧文件过期。
- **链接到期自动失效**，文件同时删除，不用手动清理。
- **不用账号**：你不用注册，对方也不用注册；链接是随机生成的，别人猜不到（但拿到链接的人都能下载）。

## 技术（给懂的人看一眼）

Cloudflare Pages + Pages Functions + R2 + D1，零构建步骤，和 ym-blog / ym-pan 同一个免费栈。

- 上传走 **R2 预签名 PUT 直传**：浏览器直接把文件 PUT 到 R2，不经过 Worker/Function（Worker 单请求上限约 100MB，传大文件必须绕过它；单次 PUT 上限 5GB）。
- 下载走 **R2 预签名 GET 跳转**：`/d/<链接ID>` 查元数据后 302 跳到 R2，下载文件名是原文件名（中文名也正常）。
- 元数据（随机链接 ID、原文件名、大小、过期时间）存 D1；过期清理靠两条线：GitHub Actions 每 6 小时调 `/api/cleanup`，加上访问过期链接时顺手删。
- 容量口径：未过期的已就绪文件 + 1 小时内新建的待上传占 10GB 上限；超了返回 413。
- 限流：同一 IP 每小时最多创建 10 次上传（IP 只存哈希）；超了返回 429。

## 本地测试

```bash
npm test   # 冒烟 21 项 + 前端 6 项 + 端到端 5 项，全部通过才算完
```

- `scripts/smoke.mjs`：SigV4 签名用独立实现重算验证；各接口的正常与异常分支；容量、限流、过期、清理。
- `scripts/frontend.mjs`：用 DOM 替身跑预览页真实脚本，模拟选文件、上传、复制、再传一个。
- `scripts/e2e.mjs`：假 R2 + 假 Functions 跑真实 HTTP，5MB 与 150MB 文件全流程字节比对。
- `npm run preview`：生成 `preview.html`（静态预览，上传为模拟，不调任何接口）。

## 别人部署和本站不一样的地方（Fork 差异）

别人拿这份代码自己部署后，和本站有这些不同：

1. **存储与数据库是空的**：R2 桶 `ym-transfer-files` 与 D1 库 `ym-transfer-db` 要自己建；本站已有的文件、链接都不会过去（数据在我的 R2/D1 里，不在代码里）。想和本站一样：按 DEPLOY.md 建同名桶和库、执行 `schema/0001_init.sql`，功能就一样了，但历史文件仍然没有——因为文件本体从不进仓库。
2. **密钥必须自己生成**：R2 的 S3 凭据（`R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`）与清理密钥（`TASK_SECRET`）是我自己的，不在仓库里；别人部署要自己在 Cloudflare 与本地各生成一份，分别填进 Pages 后台与 GitHub Secrets。没有我的密钥就签发不了上传地址——这是故意的，密钥不能共享。
3. **定时清理要自己配**：`.github/workflows/cleanup.yml` 每 6 小时调一次清理接口，需要配 `SITE_URL` 与 `TASK_SECRET` 两个 GitHub Secrets；不配的话过期文件只靠「访问过期链接时顺手删」，不会定时删，站内空间会被过期文件多占一阵子。想和本站一样：配好这两个 Secret。
4. **10GB 上限人人一样**：这是 Cloudflare 免费 R2 的上限，不是本站特有的；别人部署也是 10GB。想存更多只能付费升级 R2，然后改 `wrangler.toml` 与 `public/index.html` 里的容量常量——但单文件仍受 5GB 单次 PUT 上限约束，超过 5GB 要改成分片上传，目前代码不支持分片，想改得自己加。
5. **域名不同**：默认是 `xxx.pages.dev`；本站以后会加自己的域名，别人要加得自己在 Pages 里绑定。
6. **代码功能完全一样**：上传、下载、过期、限流、统计、中文界面，这些都在代码里，部署后直接就有，不用再配。
